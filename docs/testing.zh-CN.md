# 验收与证据

[English](testing.md) · [设计](design.zh-CN.md) · [维护](maintenance.zh-CN.md)

本文是测试规程，不是已完成的验收报告。静态 guard 和历史记录不能单独证明生产就绪。

## 语料来源

结合[语料说明](../testdata/contracts/README.md)与[判据](../testdata/contracts/ground-truth.yaml)使用，并记录准确 commit。C01–C08（包括 C06a/b）为合成样本。R01 提取自公开采购模板；R02 是人工填充并植入缺陷的衍生样本；R03 是日期/编号改写衍生样本。它们均不能证明审查过真实签署的客户合同。文件名中的 real、executed 不是来源证据。

真实文档验收还需获得授权且适当脱敏的真实合同、来源/许可记录、保留的原件与附件，以及独立复核的预期结果。不能用填充模板代称该测试。

## 盲测准备

1. 固定原文及摘要、团队 commit、成员 commit/内容摘要、资源版本和客户端构建；启动前确定立场、目标、法域及比较范围。
2. oracle、预期发现和评分答案与受测团队可访问输入隔离，只提供合同和普通用户上下文；完成后在独立评估上下文中比对。
3. 市场安装测试使用新实例，记录市场版本、安装团队/成员版本、可用云模型、审批设置和本地覆盖项。
4. 运行前定义必检项、禁止误报项、结果类别和产物检查。历史预期冲突应先核对，不能默选匹配输出的一项。

## 场景与判定

| 场景 | 必须验证 |
|---|---|
| 干净/阴性样本 | 不出现禁止风险；中性描述与风险区分。 |
| 输入缺失 | 阻断说明补救方法；条件通过继续并保留限制。 |
| 域外合同 | 不作外国法实体结论；保留转介与通用文档检查。 |
| 已知风险 | 必检发现有证据和动作；存在但不利不报缺失。 |
| 版本对比 | 比较全部已提供部件及附件；范围不完整不得判一致。 |
| 补料复审 | 新尝试保留旧产物，解释受影响及重查事项。 |
| 商业事项待决 | 交付待确认报告，不混淆合同接受与报告可取得。 |
| 导出/工具失败 | 披露失败，保留已得报告/证据，不声称虚构产物。 |

每个选定验收场景固定版本和输入**独立运行三次**。比较结果类别、必检项、禁止项、范围、原文定位和交付；措辞可以不同。报告三次结果、无法解释的变化与人工干预。超时或未完成保持未完成，不计通过。

测试可给出明确虚构回答，例如“仅模拟测试：付款事项保持待决”，并记录在证据中。模拟回答用于验证续跑，不授权真实交易。

## DOCX 验收

1. 团队在自己的运行中生成并返回可访问 `.docx`。外部生成或人工修复属于辅助证据，不满足自主交付标准。
2. 校验有效 OOXML、实际插入/删除记录和适当修订设置。仅扩展名或着色文本不足。
3. 在兼容编辑器中拒绝全部修订，比对文本与审查原文；另存副本接受全部修订，比对同意的建议措辞。披露转换/格式规范化，检查无关正文或附件没有丢失。
4. 显示全部修订并逐页检查表格、编号、页眉和分页，保留可见修订截图或渲染。隐藏修订的干净 PDF 不能证明修订显示质量。
5. 确认修改对应发现，未决选择仍有标注，原文件保留。

## 证据记录

每次保留原文摘要与来源、团队/成员/资源版本、客户端构建、provider/model、输入请求、run 标识、起止时间、步骤结果、产物路径/摘要、评估结果与每项人工修复。注明商业决定为真实、模拟或待决。仅发布获授权且脱敏的证据，提供可复验链接和 commit。

所声称范围内，验收要求规定检查通过、无必检漏项、无禁止误报、类别稳定、自主产物完整。明确排除范围，不能把窄场景通过推广到未测试格式、语言或法域。

2026-09-29 的 C01/C09a/C09b 运行（desirecore-cloud/kimi-k3，本地实例）记录在 ground-truth 的「C01 / C09a / C09b 真机实测基线」注释块。它们**不是盲测**：语料取自团队目录，ground-truth.yaml 会出现在目录列表里（没有成员打开它）；每个场景只跑了一次而非三次。应视为 intake 1.0.7 / 统筹官 1.0.22 门禁修复的回归证据，不是验收。
