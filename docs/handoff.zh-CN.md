# 合同审查团队优化：跨环境交接

[English](handoff.md) · [文档入口](../README.zh-CN.md)

本文供无法访问前任 Agent 本机的接手者使用，不依赖本地 Plan、临时脚本、实例或聊天记录。这里的任务顺序是建议执行计划，不是已完成清单。开始后在自己的环境建立权威 Plan 和进度记录，并以实际远端版本更新基线。

## 目标与授权边界

用户要求自主推进团队优化、开发、真机测试、市场发布和新人安装使用，直到所声明范围具备可复验的生产交付能力。不要只写方案，也不要每步等待“继续”。用户已授权通过 PR 提交并在独立审查、必要测试通过后合并；仍须遵守仓库保护规则和所在环境权限。

信任 Agent 执行清晰自然语言目标的能力。每名成员要有可独立验证的最小成果和“好/不好”判据；同类输入形成稳定成果类别，不要求逐字相同。不以新增强制业务 schema 代替质量判断，必要机器接口也不等于业务完成。

团队工具审批按用户要求配置全部放行；这不是接受合同条款、法律判断或签署的业务授权。真机测试选择 desirecore-cloud 实际可用模型并记录真实 provider/model，不擅自修改发布模型配置。接手者的 SubAgent 使用当前环境实际支持的模型，不假定历史模型别名仍可用。

## 设计与仍未关闭的问题

六成员目标：O0 统筹登记 → O1 输入治理 → O2 抽取 → O3 风险/法域并行 → O4 隔离独立复核 → O5 评分、报告及 DOCX → 统筹对账交付。O4/O5 是同一报告官的不同调用，不是第七人。

当前法律服务范围仅中国大陆。域外合同可进行有明确限制的通用文档治理，但须转介，不得输出外国法实体结论；已有外国法文件夹不代表支持该服务。

| 问题 | 可定位事实 | 下一步与关闭标准 |
|---|---|---|
| 运行规则冲突 | shared/rules 与本体仍有固定七步和禁止并步/重排语言 | 联合检查锁定成员指令，统一真实流程；以调用证据证明并行、复核隔离和交付顺序 |
| 事实复用与复核冲突 | 共享规则同时要求复用 confirmed 与独立回原文 | 写清适用阶段；测试故意错误候选能被复核反驳 |
| oracle 漂移 | C05/C07 是 conditional；R02/R03 有旧门禁值 pass；历史法域/签署注释不一致 | 独立复核场景和预期，再改判据；禁止按输出倒改答案 |
| 静态检查盲区 | check:gates 跳过 testdata | 增加必要的定向一致性覆盖，保留历史测量与当前预期的区别 |
| 交付被业务待决拖住 | 历史部分 O5 停在询问，未完整对账 | 待确认报告可取得；模拟业务回答可续跑但不伪造真实授权 |
| DOCX 自主交付未证明 | 历史存在人工修 YAML、外部生成 DOCX | 团队自己生成并返回真实修订文件，接受/拒绝及视觉检查全部通过 |
| 生产证据不足 | 没有当前固定版本三次完整重复与授权真实合同验收包 | 补足指定场景、真实来源、市场新装和升级证据，限定结论适用范围 |

## 历史证据：不能继承为“通过”

- 12 份文件、11 个案例编号；C01–C08 为合成样本，C06 是两份版本文件。
- R01 是公开采购空白模板；R02 是人工填充并植入仲裁机构缺陷的衍生样本；R03 为日期等改写样本。它们不证明真实客户已签合同验收。
- 前任记录的 2026-09-15/16 C07 运行使用 qwen3.8-flash，观察到 O0–O4 与部分 O5、38 confirmed 和 2 additional。62/100 是合同评分，不是团队质量分。
- 上述历史产物有人工修 YAML 和外部脚本生成 DOCX。即使结构出现插入/删除节点，也不能算自主交付。隐藏修订的干净 PDF 不证明修订视觉通过。
- 仓库没有该运行公开可复验的完整日志包。接手者无需寻找前任本地文件，应重新运行并保存可移交证据；这些叙述只是诊断线索。
- 法条静态检查曾报告 29 部，其中 10 部施行日出处待人工确认；不代表法律正确性或时效性已获专业确认。

## 可执行步骤与并行安排

估计难度仅用于分工，实际以发现的问题调整。每步完成记录修改、检查和证据；涉及运行行为的步骤都需单独真机验证，最后再跑完整链路。

| 步骤 | 工作与交付 | 依赖 / 难度 / 验收 |
|---|---|---|
| 1 | 获取团队及锁定成员源码，盘点后续提交和本地修改；创建 Plan/任务 | 小；基线与责任明确，不重置他人工作 |
| 2 | 阅读实际配置和规则，建立冲突→所有消费者→修订方案清单 | 中；覆盖共享、本体、六成员，不只改 README |
| 3 | 独立复核样本来源、场景、预期和 oracle；准备隔离盲测输入 | 可与2并行，中；预期有理由，答案不向被测者泄漏 |
| 4 | 在授权环境启动一个 dev 实例，安装基线并做最小提交/委派/产物探针 | 可与2/3并行，中；记录构建和模型，不同时启动重型实例 |
| 5 | 同步共享与成员调用规则，明确证据传递和 O4 独立性 | 依赖2/4，较大；独立 review 后验证真实调度、错误候选复核 |
| 6 | 修正 oracle 及必要定向检查，保留历史记录身份 | 依赖3，中；正例、负例及门禁差异明确，不迎合输出 |
| 7 | 分别验证 intake、extractor 最小闭环及补料处理 | 依赖5/6，中；缺失/未知/不适用不混淆，原文可追溯 |
| 8 | 分别验证 risk、jurisdiction，并验证 O3 真并行与域外转介 | 依赖7，中；禁止误报和法域边界均通过 |
| 9 | 验证 O4：准备错误/无法定位/遗漏候选，检查独立回原文 | 依赖8，中；不是复述前序结论，回执类别完整 |
| 10 | 修复 O5 和统筹对账，验证待决报告、失败恢复和文件取得 | 依赖9，较大；真实产物与账本一致，不无限等业务决定 |
| 11 | 打通自主 DOCX，验证原文保留、真实修订、接受/拒绝及逐页视觉 | 可提前独立探测导出，集成依赖10，难；人工修复不得计通过 |
| 12 | 固定版本，对代表性场景各跑三次隔离测试；另跑授权真实合同 | 依赖7–11，难；类别稳定，无必检漏项/禁止误报，披露限制 |
| 13 | 更新版本/锁/双语文档，经各仓库 PR 审阅、测试后合并 | 依赖12；核对规范内容摘要，不能手造 hash |
| 14 | 更新市场来源，独立新实例从市场安装并模拟新人完整交付 | 依赖13，难；版本、模型、真实调用、报告和 DOCX 可核验 |
| 15 | 单独验证已有实例升级/回退，最终复核证据与发布声明 | 依赖14，中；保留用户原件，不把未验证范围称生产就绪 |

建议并行分工：协调者单写 Plan 并集成；规则/成员工作者负责步骤2/5；评测工作者负责3/6；平台/导出工作者负责4/11的通用能力诊断。文件所有权不得重叠。每个委派携带基线、目标、相关源码入口、负责文件、非目标、验收及证据位置，并提醒不覆盖其他人的修改。独立 reviewer 不由原实现者自评代替。

## 平台边界、环境和安全

平台提供安装、文件访问、委派、模型路由、工具与产物能力；团队负责合同事实、法律/商业判断、覆盖和修订建议。权限拒绝、错误参数或成员漏用工具先核实归因，不能看到导出失败就直接改平台。

平台修改前阅读该环境 DesireCore 仓库的 AGENTS.md、架构和相关模块/API，使用不同 Agent review；修复后重新真机测试。团队仓库基线目标为 main，平台目标按其仓库规范，不能机械套用。

不得运行全量测试或不受控并行重任务。平台采用受影响范围测试；团队现有静态入口：

```sh
npm ci
npm run check:gates
node shared/resources/jurisdiction-packs/jurisdiction-cn/statutes/check-temporal.mjs
```

这些命令不调用模型、不验 DOCX 外观、不证明法律正确性。不要修改安全软件设置或将调查 Defender 当功能验收前置；实际阻断时记录具体错误。

本文不携带账号密码、token、私有合同或机器路径。使用接手环境获授权的登录方式；缺凭据、平台源码访问或真实合同授权时，只请求具体缺项，同时推进无阻塞工作。发布证据须脱敏，禁止将秘密写入 Git。

## 验收记录与最终交付

新运行至少记录：团队/成员 commit 与摘要、知识包版本、客户端构建、provider/model、输入来源及摘要、角色/法域/目标、run 标识与时间、各步骤真实回执、产物摘要、评估结果、人工干预、模拟/真实/待决业务确认。在接手环境选择可访问且获授权的证据存储；仓库可保存脱敏验收报告和稳定引用，不假装旧本地证据已经上传。

DOCX 必须由团队生成；拒绝全部修订后核对原文，接受全部后核对建议，显示全部修订逐页核对正文、表格、编号、附件和分页。合成、公开模板与授权真实合同分别报告。

最终提供：已合并 PR、实际发布/市场版本、可复验的验收报告、三次一致性结果、真实合同与 DOCX 证据、已知限制及回退方式。若外部授权缺失，明确该项未完成，不伪造或扩大成功结论。
