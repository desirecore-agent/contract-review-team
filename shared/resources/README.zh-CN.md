# 共享审查资源

[English](README.md) · [团队设计](../../docs/design.zh-CN.md)

这些文件提供可复用审查知识，不代表每项检查已经执行，也不保证法律库始终最新。仓库设计说明替代原先未入库的 .design 蓝本引用，不冒充博客原文。

## 清单与范围

| 路径 | 作用 |
|---|---|
| business-ontology/ | 合同概念、关系、动作、不变量和负例 |
| jurisdiction-packs/base/ | 通用缺失条款及标尺检查 |
| jurisdiction-packs/jurisdiction-cn/ | 当前支持的中国大陆包 cn-v3 |
| jurisdiction-packs/jurisdiction-cn/statutes/ | 法条正文、索引、时点元数据及静态检查 |
| jurisdiction-packs/jurisdiction-us/ | 已有资源，不代表本团队提供美国法服务 |
| jurisdiction-packs/custom/ | 组织自定义红线 |
| risk-lexicon/ | 双语候选触发和误报抑制 |
| severity-mapping.yaml | 严重度映射数据 |

CN 包声明 knowledge_base_version 为 2026-09-05，较旧的 updated_at 不能另行证明时效。法条索引声明 29 部、4,096 条、1,270,526 字节；引用时须读取正文及 temporal 元数据，数量不能证明法律正确性。

## 使用原则

先读包元数据，再选资源。可配置业务政策的概念优先级为 custom > jurisdiction > base，但自定义政策不能排除强制性法律。覆盖必须说明对应规则和理由；资源缺失或沉默都不等于通过。

触发词只提供候选。风险成员必须定位原文，检查限定条件和反例，再按规定路线解决，见[词库说明](risk-lexicon/README.zh-CN.md)。

法域成员负责法律适用和来源核对，保留合同日期、相关法律事实日期、法律版本、来源及不确定性。不能仅因某法律文件在目录中就认定适用。缺失或不确定证据必须明确限制或转介。

报告官须独立回到原文，上游 confirmed 标签不能替代 O4 复核；统筹官对账真实回执和未覆盖项，不得替成员补造完成记录。

## 已知设计债务

注入的[共享规则](../rules.md)和[本体规则](business-ontology/rules.md)仍保留固定七步要求，与当前 O0–O5 并行观察设计冲突；共享说明同时存在已确认事实复用和独立重新取证要求。本次说明不覆盖或修复运行指令，见[测试及缺口](../../docs/testing.zh-CN.md)。

## 维护与扩展

1. 确定来源、消费者、规则 ID 及受影响正反例。
2. 在独立行为变更 PR 修改资源和元数据，保持双语语义一致。
3. 检查引文、时点、反例及非预期政策覆盖。
4. 运行定向静态检查、受影响成员测试及干净安装端到端审查。
5. 发布报告记录精确团队、成员、知识包版本和证据。

新增域外法文件夹不等于启用该法域。必须先明确服务范围，完成专业来源复核，协调成员指令和转介行为，再进行专门真机验收。

命令、版本锁、发布及回退见[维护说明](../../docs/maintenance.zh-CN.md)。静态检查不验证全部语料或智能体行为。
